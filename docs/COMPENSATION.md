# 薪酬约束语法与跨岗位比较合同

## 背景

招聘文案中的月薪区间、额外月数、固定/目标奖金与年包总额是**相互约束**的金额，
不能把所有数字简单相加。旧的 `salary.parse_salary` 只抽取第一个范围并折算月薪，
服务于台账展示；本文件描述新增的约束层，它与旧解析器并存，不改写任何生命周期事件。

约束层由三个模块组成：

| 模块 | 职责 |
| --- | --- |
| `comp_parser.py` | 文档化中文金额语法解析，保留原文与每个数字的来源 span |
| `compensation.py` | 有界精确有理数（`Fraction`）可行年度收入集合与冲突报告 |
| `comparison.py` | 稳健优势 / 机会优势两种跨岗位比较合同 |
| `comp_report.py` | 基于 Store 只读数据的查询与 Markdown 渲染（经 `report.py` 转出） |

## 中文金额语法（唯一受支持集合）

输入先做 NFKC 归一化；仅当逗号两侧都是数字时才视为千分位删除，其余逗号是分句符。
分句符：`, ， ; ； 、 。`。每个片段按关键字归类，未识别片段记入 `parse_errors`
而不是静默丢弃。

1. **月薪区间**：`20-25K`、`1.5-2.5万`、`40K`，可附 `12-24薪`。
   年基本工资 = 月薪区间 × 月数。区间一端省略单位时复用另一端单位（`37-38万`）。
2. **固定奖金区间**：含 `固定奖金`/`固薪奖`，属于保证收入。
3. **目标奖金区间**：含 `目标奖金`/`绩效奖金`/裸 `奖金`。裸奖金默认是目标奖金，
   **不是保证收入**；其上限永远不进入严格/保证组成。
4. **年包总额约束**：含 `年包`/`总包`，如 `年包35-40万（含奖金）`。它注明
   “含上述各项/含奖金/含提成”，因此与各组成之和取**交集**，绝不相加。
5. **保底**：含 `保底`/`保障`，如 `保底37-38万/年`。独立出现时它本身就是可行
   年度收入集合；与其他组成同时出现时作为下界约束。
6. **提成上不封顶**：含 `上不封顶`/`不封顶` 时上界保留为无穷（`Interval.high=None`），
   不用任意大整数代替。
7. **币种**：前缀 `CNY/RMB/USD/EUR/HKD`，默认 CNY（RMB 归一为 CNY 展示）。
   不同币种照常解析，但缺少本地换算依据时**拒绝比较**。

## 精确有理数与可行集合

所有金额都是 `fractions.Fraction`：无浮点舍入、无比较前取整。`Interval` 是闭区间，
`high=None` 表示正无穷，支持 `intersect` 与 `add`。

求解规则：

- 严格/保证区间 = 基本工资 + 固定奖金（加 `保底` 下界，若同时存在）。
- 目标/浮动区间 = 零 + 目标奖金 + 提成（可能无穷上界）。
- 可行年度收入 = 严格与浮动之和，再与年包总额、保底下界依次取交集。
- 交集为空时返回 `Conflict(left, right, 两个区间, 说明)`，不产出排名。

### 合成示例 A

`20-25K·14薪，目标奖金0-6万，年包35-40万（含奖金）`

- 基本工资：280000-350000 元/年（严格）
- 目标奖金：0-60000 元/年（非保证）
- 朴素相加上限会得到 410000；再与年包 350000-400000 取交集后
  **可行年度收入 = 350000-400000 元/年**。
- 错误算法 `28-35万 + 0-6万 + 35-40万 = 63-81万` 被明确排除：年包是包含关系。

### 无解示例

`月薪40K·14薪，年包30万含奖金`：基本工资 560000 已超过年包上界 300000，
冲突报告为 `component_sum ∩ package`，并附上 560000 与 300000 两个精确区间。

## 两种比较合同

输入是两个 `Feasibility`；任一无解或币种不同时，两个合同都返回 `refused`。

| 合同 | 成立条件 | 失败返回 |
| --- | --- | --- |
| 稳健优势 `robust_advantage` | A 的**每个**可行收入都严格高于 B 的**每个**可行收入，即 `min(A) > max(B)` | `indeterminate` + 反例区间见证 |
| 机会优势 `opportunity_advantage` | **存在**一个可行 A 收入高于某个可行 B 收入，即 `max(A) > min(B)` | `indeterminate` + 反例；理由中注明“不等同于保证优势” |

边界语义：相等不算严格优势；A 上界无穷时稳健合同必然不可确定，机会合同仍成立并
给出有限数值见证。对 A（35-40万）与 B（保底37-38万）：稳健合同不可确定
（反例 A=350000 vs B=380000），机会合同成立（见证 A=400000 > B=370000）。

## 数据来源与生命周期隔离

- `parse_detail_page` 在 `JobObservation.compensation` 上挂接 `CompensationPlan`，
  该字段**不进入** `content_payload()`/`tracked_values()`，因此 content hash 与
  NEW/CHANGED/DISAPPEARED/CLOSED/REOPENED 事件完全不变（由 golden 与生命周期测试守护）。
- `comp_report` 只通过 Store 的只读方法读取 `jobs` 行与 `job_snapshots.payload_json`
  中的薪酬原文，不读取 `salary_min/salary_max` 做排序，也不写任何表。
- 每个解析数字携带 `(start, end)` span，可从原始输入逐字符重建；解释载荷同时给出
  严格/目标组成、年包约束、可行区间、冲突与数值见证。
